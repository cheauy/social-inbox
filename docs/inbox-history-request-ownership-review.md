# Back/Forward request ownership repair

Base: deployed fb13e1e0a3e4004dd879c4273b8b5b358d3404a0. Separate Temp checkout; original dirty worktree unchanged. No push/deployment, rollback, live SQL, permission changes or customer actions.

Reproduced cause: All settled, then Back starts a cold Pinned request while settled state remains All. Forward returns to All before Pinned completes. The deployed effect returns early because settled state already has the All key, leaving the Pinned controller/generation active. Its later response publishes Pinned state while URL/request still says All. After All cache expiry/invalidation the display becomes empty/loading, but no All request owns that loading state. An unrelated later recovery event can restore it. This matches the supplied live observations; exact production request timing was not instrumented here.

Repair: track navigation key separately from settled-state key. Every committed key change transfers ownership and cancels the preceding request before considering its destination loaded. Returning to retained All starts quiet reconciliation and requalifies its visited/recent IDs. Late catch/finally from a retired generation cannot consume or schedule the new view's recovery. Initial hydration still does not refetch; bounded cache, first-page fetching, active selection and existing predicates remain unchanged. One runtime file changes: lib/inbox/use-conversation-pages.ts.

The new deterministic test fails on deployed code because the pending Pinned signal is not aborted. Both new tests pass after repair, including cache expiry at 33.4 seconds, ignored-abort late delivery, Forward reconciliation, and a pending live event arriving before the old finally. The old finally cannot enqueue new-owner work; the active request retains its event and follows up once.

Native Chrome uses real deployed/repaired hooks and actual History Back/Forward in a synthetic list. Cache age is advanced by 33.4 seconds, Pinned response delayed 400ms, Forward performed after 50ms, All response delayed 100ms. Deployed code ends with URL/view All, zero rows/loading and only a Pinned request. Repair ends with All's 30 rows, no loading, requests Pinned then All and Pinned aborted. Even an ignored-abort Pinned response cannot overwrite All. The browser fixture is not the full authenticated app or a production network trace.

Validation: 76 focused regressions pass, including sends, album targets, voice controls, view qualification/counts, empty/errors, caches/permissions, realtime, pagination, history scroll and existing URL navigation. TypeScript and runtime lint comparison pass with no introduced findings. Final local Webpack production build uses synthetic Supabase configuration and existing font downloads.

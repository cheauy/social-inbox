# Immediate Unread membership when switching conversations

Base: `6d347a0e2be632a05557ac7c570b36516c37c874`. Prepared in a separate Temp clone; original dirty checkout unchanged. No push, deployment, production SQL, or customer messages.

The selection handler already selects locally and swaps a warm message cache without waiting for read PATCH or router refresh. The clarified delay instead came from paged ConversationList using `pager.rows` directly, bypassing the immediate unread predicate, and using only server aggregate counts. A coalesced server qualification later removed all read rows together. Its generic loading flag also displayed skeletons while revalidating an already loaded empty page.

The paged list now applies its known unread predicate immediately; selected conversation state and the message cache are not cleared. Server qualification remains responsible for complete search, Smart Views, scope, and history. Counts reconcile unread changes for already qualified page rows against their server snapshot; other view/status aggregates remain server-owned. Quiet empty-page refreshes preserve the empty state, while an actual new-view load still has loading feedback. A failed automatic read restores only its optimistic count, keeping selection and newer incoming/manual-unread updates. Existing failure refresh and authorization stay intact.

Validation: 36 focused tests pass across paging, duplicates, late responses, tenant scope, history scroll, read failure/offline, incoming races, immediate unread aggregates, and empty revalidation. TypeScript passes. Touched-file lint comparison introduces zero findings (existing InboxView 21 and ConversationList 6 findings remain; paging hook clean). Production Webpack build passes with synthetic Supabase settings and network access only for the existing Google Fonts imports. Default Turbopack cannot build this Temp node_modules junction because it points outside its filesystem root; restricted-network Webpack fails fetching fonts. Neither failure was described as a successful check.

Reproducible synthetic Chrome comparison: run `node tests/inbox-unread-switch-browser-build.cjs`, then open `%TEMP%/tenh-switch-browser.html` with Chrome's sandbox enabled. It bundles the real old/new paging hook, with a small list shell and the production unread predicate. It does not hydrate the full authenticated Inbox. With fixed 600ms page response latency, baseline retains all three read rows/count 3 at 240ms; first row removal occurs at 910ms. New behavior removes each row and decrements its count within the first 10ms observation. A subsequent empty refresh shows 600ms sampled skeletons before, zero after. Final selection stays on the third chat. Chrome virtual-time observations are fixture results, not production click latency or paint benchmarks.

Evidence: `%TEMP%/tenh-switch-final-tests.txt`, `tenh-switch-browser-dom.txt`, `tenh-switch-webpack-build-network.txt`. Browser fixture has no credentials, provider traffic, real messages, or database writes. Supplied video independently shows approximately 4.32s and 2.83s row retention after leaving the first two read chats; its mouse-down times are unknown. Only Unread was demonstrated in that clip. Other filters, caches, paging, read barriers and realtime regression tests remain covered without a broad switching rewrite.

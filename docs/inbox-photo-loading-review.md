# Outgoing image loading and preview review

Confirmed code causes: single photos had only `max-height` and width, so an undecoded image supplied no useful height and its bubble could collapse. Realtime/history reconciliation preferred a saved URL over the local blob without retaining a separate preview, causing a new image load while the outgoing photo was already available locally. The supplied parent pixel inspection described the short blue bubble; local screenshot materialization failed because the current supported Library helper requires `os.setxattr`, unavailable in Windows Python. No local screenshot inspection is claimed.

Single photos now reserve a responsive 4:3 frame (300×225 at the normal 300-pixel column), using contain sizing so the whole photo remains visible. Albums keep their existing square/3:2 cell geometry. Loading shows a neutral image glyph with screen-reader status, without a visible loading line or a collapsed bubble. Final failure retains the frame and presents an accessible Photo unavailable/Retry photo control. Retry only loads the image; it does not resend the message or open its viewer.

Client-only local preview fields retain outgoing blob previews through send-response, Realtime, polling/history and cached reopening while canonical saved attachment URLs and album payloads remain authoritative. Partial album `saved_indices` map to the exact original local photo. Workspace/conversation/direction/provider identity checks prevent reusing another message's preview; deletion clears it. No transient field is written into server storage or provider payloads. Successful source tracking is tab-local and bounded to 256 strings, not a persistent image cache or preload.

An available local blob is tried first, followed by the saved URL and one authorized thumbnail recovery for the same selected photo. An unresolved optimistic message ID never triggers server recovery. Each explicit manual retry starts a new bounded attempt. Lazy loading and asynchronous decoding remain; there is no background image prefetch. The original saved URL remains available for existing copy/download flows.

TENH CHAT LOCAL WEBSITE PERFORMANCE AUDIT — October 7, 2026

Outcome
One product file changed: the dashboard notification header. Correct notification content publishes as soon as its own request finishes, and overlapping mount/bell/resume reads share one pending request per endpoint. No completed-response cache, extra polling, new subscriptions, route prefetch, dependency, schema or infrastructure change was introduced.
This is a verified local improvement, not proof that every page is faster or that production bills are unchanged. Full-site authenticated latency, provider usage and physical-device measurements remain UNVERIFIED.

Root causes and fixes (paths relative to C:/Users/TUF/social-inbox)
1. components/dashboard/team-notification-center.tsx:432: the original loader awaited both responses and both JSON bodies before publishing notifications. A slow announcement delayed usable team content. Each endpoint now publishes independently.
2. Same file:376 and :435: mount, repeated bell opening, foreground resume and polling could start overlapping pairs. A component-owned pending map shares only overlapping GETs (maximum two entries); settled reads are removed. Every subsequent non-overlapping refresh still authorizes on the server.
3. Same file:378, :438, :482, :527, :656: abort plus generation ownership retires old responses on unmount, workspace invalidation, realtime mutation and optimistic actions. Controller identity prevents old cleanup from removing a newer read. 401/403 clears displayed private state and cancels the other read. Existing cross-workspace notification aggregation remains unchanged.
4. Same file:481 and :1008: loading starts from initial state; explicit retry changes loading immediately. Redundant synchronous state updates in the mount effect were removed. No separate render-count improvement is claimed.
5. tests/website-read-efficiency.test.cjs:20: the timer double previously invoked 30- and 60-second callbacks in one synchronous turn. It now settles asynchronous work between cycles, so the regression test verifies real polling rather than artificially merging distinct polls.

Equivalent benchmark method and limits
Five component-cold mounts and five warm bell cycles per viewport, for both the saved starting header and final header. Same production React, webpack settings (minification disabled for both), generated app CSS, synthetic dataset and loopback server. The fixture verifies the actual styled bell before measuring. A component-cold mount is not a browser/network-cold whole-page load.
Real HTTP requests execute the existing two API GET handlers through the test loader; authentication and Supabase are mocks. Dataset: one member, one notification, one announcement, no due reminders/personal channel. Fixed endpoint delays: team 20 ms, announcement 180 ms; mock DB query delay 10 ms. Handler compilation is primed outside measurement. API bodies are no-store. Viewports emulate layout on this desktop, not physical phones/tablets or throttled cellular networks.
The final runs below were repeated after the production build, with built CSS loaded. Earlier exploratory runs without CSS are excluded from delivered evidence.
Cold feedback measures opening the panel; cold content measures visible correct notification text. Announcement completion remains separate. Warm content is already-held component state, not freshly completed server work. HTTP handler durations below are recorded separately; they are not Vercel telemetry.

Reproduction

Set TENH_PERF_OUTPUT to an absolute disposable folder and TENH_PERF_BASELINE to that saved file; run node tests/website-header-performance-browser.cjs to build baseline. Clear TENH_PERF_BASELINE, set TENH_PERF_SERVE=1, and run the same command to build final/start the loopback server. Through permitted browser controls open ?mode=baseline and ?mode=final at each viewport, click Run benchmark and verify passed=true. Each page records five cold/warm cases and saves its JSON locally. Stop the server and reset viewport afterward. No real backend credentials are used by the fixture.

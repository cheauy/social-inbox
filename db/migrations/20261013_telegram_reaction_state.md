Normalization contract
A JSON object at raw_payload.message is authoritative, including an empty object. Otherwise the parser and SQL use the root payload (null, array and primitive message wrappers fall back to the root). An album ID is supported only when its JSON type is string and it contains 1 through 64 ASCII digits. Leading zeros are preserved and remain distinct. No trimming, numeric conversion, truncation, hashing or varchar length cast is used. A present unsupported ID rejects the selected target; it never falls back to a single-message provider action. An absent album field preserves ordinary m:MID behavior. An empty message object cannot borrow root metadata, so it fails eligibility and produces no album members. SQL exclusion is not proof of single-message eligibility.

The index and four migration membership expressions use the same nested CASE: check JSON string type, then length 1..64, then length(translate(value,'0123456789',''))=0, then emit the original text with explicit pg_catalog."C" collation; all other inputs become NULL. This guards the Btree key itself, rather than relying on route validation or a partial predicate to protect writes. The predicate is exactly that bounded expression IS NOT NULL. Maximum album key text is 64 ASCII bytes. Objects, arrays, numbers, booleans, null, empty text, 65+ characters, whitespace, Unicode digits and line suffixes are unsupported and excluded without rewriting stored JSON.
